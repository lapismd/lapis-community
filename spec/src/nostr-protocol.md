| LC-NOSTR-007 | The NIP-29 community source and its registry adapter MUST treat relay URL plus group ID as room identity, read authoritative state only from the owning relay, allow configured mirrors to supplement content reads, and publish commands only to the authority. When public-room discovery is enabled, the source MUST discover non-hidden kind `39000` groups from the authority, classify channels and forums from `supported_kinds`, subscribe to their subsequent state and content, and merge them with explicitly configured rooms without duplicates. A locally persisted relay-URL change MUST rebuild the source session before it can become the new authority. Latest valid kind `0` metadata MUST project into normalized member and personal-settings models without mutating the supplied signed events during verification. Profile edits MUST merge and publish kind `0`; custom emoji edits MUST replace only the connected author's parameterized NIP-30 kind `30030` set, while the read model deterministically merges community sets. Group reactions MUST carry their NIP-29 `h` context so public readers can retrieve them. Channel projections MUST keep replies out of the root timeline while retaining them in threads, aggregate root reply and reaction summaries, retain up to three most-recent unique reply participants, and expose the latest reply timestamp; the registry adapter MUST preserve bounded count-backed discussion reads through the same relay factory and use standard base64 for Nostr HTTP authorization. |
| LC-NOSTR-008 | Direct messages MUST use NIP-17 sender and recipient gift wraps backed by NIP-44, validate the wrap, seal, and rumor chain before materialization, and remain unavailable when the connected identity lacks encryption support.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| LC-NOSTR-009 | Cross-device read markers and preferences MUST use encrypted-to-self kind `30078` events with per-device addressable slots, deterministic monotonic/LWW merging, local-first loading, bounded payloads, and no plaintext logging.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| LC-NOSTR-010 | Community management MUST encode NIP-29 create, metadata update, owner delete, moderator delete, group delete, join, leave, add-member, and remove-member commands as kinds `9007`, `9002`, `5`, `9005`, `9008`, `9021`, `9022`, `9000`, and `9001` respectively, leaving relay acknowledgements authoritative. Reaction toggles MUST publish kind `7` once and delete the connected author's reaction on the second toggle; custom reactions MUST carry NIP-30 emoji tags. Public message links MUST encode NIP-19 event, author, and relay hints or use an injected host link builder. Direct messages, replies, reactions, and deletions MUST remain encrypted NIP-17 rumors, route recipient and sender wraps to each participant's latest advertised kind `10050` inbox relays, reject recipients without an advertised inbox, and never expose decrypted content to logs or public links.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Plugin support discussions use one NIP-29 group per plugin. NIP-7D kind `11`
topics, NIP-22 kind `1111` replies, and NIP-25 kind `7` reactions remain
ordinary signed relay events. Clients render them in posting order and retain
reply context without inventing a second persistence model.

Private kind `14` rumors are materialized only after their NIP-17 gift wrap and
kind `13` seal validate and decrypt for the connected identity. Application
state uses eight recent per-device NIP-78 slots, a 32 KiB plaintext ceiling,
two-second debouncing, and message/thread marker pruning before room cursors.
