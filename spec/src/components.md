# Community Components

For LC-UI-036, the Docker application story MUST seed the same NIP-34 project,
repository, task, pull-request, and review graph through the production
WebSocket and NIP-98 source before exercising the Buzz-aligned workspace.

For LC-UI-036, a restored project catalog MUST keep project navigation and
content available during live refresh, show a non-destructive cached status
with the last verified time, and distinguish a live-refresh failure from an
initial catalog failure instead of replacing restored content.

For LC-UI-036, a connected external repository's contextual GitHub action MUST
open an administrator-facing connection dialog that shows active and error
states, sanitized failure detail, last-check time, and revalidation. The dialog
MUST allow a complete connection to be added or replaced using mounted
credential references, keep those reference inputs masked, and never prefill
them from a public connection response. Repository attachment MUST continue to
offer only active installations.

For LC-NOSTR-020, normalized room and member models expose additive posting
policy, role-definition, multi-role, and administrator state while retaining
the legacy singular member role. Presentation treats relay administrators as
read-only and does not infer a portable permission matrix from role labels.

For LC-UI-019, the shared channel and forum browser MUST use the application's
compact dialog type scale for its title, search, tabs, actions, results, and
empty state rather than inheriting large command-palette typography. Joined
room results MUST expose a destructive Leave button in place of Join.

For LC-UI-031, the channel and forum member command MUST use the same compact
dialog title, search, group-heading, result, and secondary-text scale as the
surrounding Community workspace.

For LC-UI-016, a channel bound to a project MUST place its Add files repository
action first in the same action-card row as Browse channels and Create a
channel. The row MUST span the available content width while retaining the
cards' shared fixed footprint and compact title typography, and MUST wrap only
when the available width cannot contain the next card. Private-room title icons
MUST share the compact size and alignment of the other room-kind icons.

For LC-UI-036, the repository Files surface MUST select its first file when no
path is active, retain the active selection when that row is selected again,
and replace the right-hand preview with an accessible skeleton while the active
file contents are loading.
Initial repository Files loading MUST use an accessible skeleton that preserves
the file-list sidebar, divider, preview header, and code-line geometry. Project
Overview loading MUST use an accessible Markdown-shaped skeleton with heading,
paragraph, section, and code-block geometry.
Selecting a file MUST fetch only that blob without reopening the project
catalog, work-item subscriptions, repository capabilities, refs, or tree.
Recursive file discovery MUST bound concurrency while loading independent
directories in parallel.
When projects use the active Community relay, their presentation MUST wait
until relay and identity restoration settle and MUST resume after reconnect.

For LC-UI-036, aggregate repository and task collections MUST split into
collapsible Mine and Other groups. Mine repositories are authored by the
connected member; Mine tasks are authored by or assigned to that member.
Collapsed groups MUST retain their item count. Repository rows MUST expose a
Buzz-aligned proportional activity bar with independently labelled commit,
review, and task segments, and their relative time MUST reflect the newest
activity represented by the row.

Every member identity rendered by Projects directory cards, repository, task,
review, and commit rows, task and review details, activity, or contributors
MUST use the shared member hover card with profile, Message, and Wave actions.
Overlapping compact task avatars MUST retain separate interactive triggers and
a surface-coloured ring so every member remains visually distinct.

For LC-UI-036, pull-request review comments MUST project visible NIP-25 kind
`7` reactions into the existing `CommunityMessage` reaction bar, including
aggregate counts and the connected author's selected state. Hovering a
reactable review comment MUST expose the shared add-reaction action. When the
repository's collaboration backend is GitHub, that picker MUST contain only
GitHub's supported thumbs-up, thumbs-down, laugh, confused, heart, hooray,
rocket, and eyes reactions. Selecting an unselected reaction MUST publish a
project-scoped kind `7` event; selecting the connected author's existing
reaction MUST publish its kind `5` deletion so the relay can reconcile the
change with GitHub.
