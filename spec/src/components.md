### Canonical UI composition

The machine-readable `src/components/ui-catalog.json` is the mandatory starting point for UI work. `pnpm ui:catalog <pattern>` identifies the public import, compiled consumer example, production stories, variants, and required states. `Community/Patterns` renders and displays source from the same example files. Existing feature-story URLs remain stable.

Generic DialogFrame and ConfirmDialog/ConfirmButton belong to Design Core. DialogFrame supplies compact (28 rem), form (40 rem), and wide (68 rem) viewport-bounded recipes, title and close controls, an optional sidebar, a ScrollArea body, and a footer outside the scroller. Pages pass snippets and form identifiers; they do not style the frame internals. Confirmations are compact centered modals with outline Cancel, destructive actions where appropriate, pending guards, and retained errors for retry.

Community owns its semantic typography tokens (body, secondary, section, dialog, page, and compact avatar initials), avatar editor, member navigation, emoji/reaction controls, Markdown projection, and skeleton recipes. Image-less `CommunityMemberAvatar` instances derive a deterministic Buzz-compatible fallback tone from the normalized display name and pair each background with an accessible foreground color; Community uses darker shades where Buzz's source palette does not meet the required contrast at Community avatar text sizes. CommunityChatComposer form mode inserts a newline on Enter and leaves saving to the enclosing form; default chat mode retains submission behavior. Names, searches, keys, URLs, code, and structured tool payloads retain suitable structured controls. Decorative avatars inside an interactive card or editor are valid; author identities use CommunityMemberHoverCard with CommunityMemberAvatar and existing profile callbacks.

Inbox conversation-list skeletons MUST have padding on all sides of the item list, and Inbox message skeletons MUST have conversation-pane padding during both initial Inbox loading and selected-thread loading. Selecting a different Inbox conversation MUST show that message skeleton until the selected conversation's content is ready, and MUST retain visible messages when cached content is already available. Initial loading MUST show a skeleton representing the destination: gallery, timeline, messages, details, or repository rows. Refreshes MUST retain existing content. Pagination MUST place placeholders at the loading edge. Accessible loading announcements MAY be visually hidden; action-level pending labels remain valid. Empty and error states are distinct from loading. Visual resemblance requires human review in addition to automated geometry and transition tests.

`check:ui` parses Svelte, TypeScript bindings, and CSS to reject governed primitive use, handcrafted overlays, raw prose textareas, independently initialized emoji pickers, custom typography, and overrides of governed component internals. Diagnostics name the file, rule, canonical replacement, and example. Each exception must name one exact file and symbol, rationale, requirement, and verification story. Inline suppression and blanket directory exceptions are invalid. Contract stories verify scrolling, footer stability, focus, picker selection, form submission, navigation, Markdown, reactions, and loading transitions.

Identity defaults include Message and Wave in every contact popover, disabled when the consumer cannot perform the action. The avatar group composes a complete CommunityMemberHoverCard for each member rather than making the group one profile target. Message reply summaries compose that same group for participant identities so each avatar opens the shared contact popover and keeps its hover target at the avatar icon size; the reply-count chip is a separate compact `CommunityChip` that opens the thread. Explicit inline mentions and mentions rendered by CommunityMarkdownContent share the same callbacks, profile navigation, and popover actions; optional contextual actions remain supported.

Composer member widgets mount the same `CommunityMemberHoverCard` used by Markdown. Inline identities fit within the surrounding line height, with centered, unclipped initials; they must not enlarge prose line spacing. The UI policy inspects TypeScript editor adapters as well as Svelte and CSS, rejecting imperative recreation of governed controls and lazy emoji-picker initialization.
