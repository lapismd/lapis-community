The package uses Design Core controls for shared interaction primitives. Local
CSS owns the Discourse-inspired registry layout and the Slack/Buzz-style
community content because timeline, post stream, room navigation, and
custom-element boundaries are application-specific. Design Core App Shell owns
the workspace geometry, selectors, offstage inertness, focus restoration, and
automatic desktop/mobile presentation. Relay adapters will map Nostr-derived
state into normalized community models through the public controller.

interaction plays remain attached only where a real control produces a visible
or accessible result. Every `defineMeta` points at a public production component.

The Inbox, navigation, and workspace wrappers keep explicit docs source so
Storybook does not present test-runtime internals as consumer markup. Loading,
empty, disconnected, permission, and publish-failure states are owned by the
controller/runtime catalog and may be expanded without creating domain-only
fixtures.

After this audit, `RegistryCommunity.stories.svelte` was added as the requested
relay-integration lifecycle story. It renders the production component with a
reusable signed-event scenario and runs through the same memory/Docker backend
selector as the full workspace story.

## Full application action inventory

| Surface                         | Visible result and owner                                                                                                                                                                                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Room toolbar and settings       | Member count opens the reusable member command; Type and Visibility open the shared room editor; ID copies with a toast; Leave and Delete confirm before controller commands. Thread and settings panels remain mutually exclusive.                                        |
| Navigation                      | Section create/browse/new-message controls open production dialogs or the direct-message compose view. Room hover, keyboard, and context menus copy, update read/star/mute/hide state, assign custom sections, open settings, leave, or delete through controller actions. |
| Messages and composers          | Reaction badges and the standard/community emoji picker call the controller toggle; Reply opens a focused thread or direct reply context; copy and delete live in the hover/focus action menu; successful and rejected actions produce toasts.                             |
| Forums and DMs                  | New topic publishes kind `11`; forum row menus expose portable actions; New direct message collects up to eight recipients and publishes through the controller's NIP-17 inbox-relay routing.                                                                              |
| Profile, search, and extensions | Status publishes through the controller; search shows rooms, loaded/relay messages, and members; unsupported Buzz-only controls are omitted unless the host provides the matching typed extension.                                                                         |
