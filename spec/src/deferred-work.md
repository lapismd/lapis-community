# Deferred work

This is the canonical ledger for work that Community deliberately does not
claim as current behavior. It records the owner and the condition that must be
met before each item can move into an implementation requirement. Completed
items are removed from this table in the same change that adds their normative
requirement and verification evidence. The sibling relay's detailed native Git
roadmap remains authoritative for relay implementation details; the Forge rows
below track the corresponding Community product boundary. The sibling
[controller deferred-work specification](../../../nostr-agent-controller/spec/src/deferred-work.md)
owns runtime exit conditions; the Agent rows below track the matching Community
product boundary.

States have precise meanings:

- **Planned** means the outcome is accepted but has no scheduled release here.
- **Protocol decision** means the wire, custody, privacy, or authority model must
  be approved before implementation.
- **External dependency** means another package or application must release a
  usable public contract first.
- **Manual gate** means implementation may be complete but a human must approve
  publication, deployment, credentials, or visual baselines.
- **Deliberate exclusion** means the feature is outside the current product
  boundary and requires an explicit scope decision to enter the roadmap.

The relay's [Deferred forge work](../../../nostr-relay/spec/src/roadmap/deferred-forge-work.md)
contains the lower-level acceptance details for extra protected-branch
patterns, automatic revisions, merge-queue leftover, repository retirement, and
provider coverage. Live default-branch protection and the native WalGit merge
coordinator are implemented; DEFER-FORGE-001 is closed by removal.
Community must update both ledgers when one of those shared boundaries changes.
